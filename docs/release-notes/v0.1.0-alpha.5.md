## 한국어

### Windows 두 명령 자동 등록

Windows ZIP은 `kubewiser.exe` 한 개와 `install.ps1`을 제공합니다. 압축을 푼 폴더에서 PowerShell로 한 번 실행하세요:

```powershell
.\install.ps1
kubewiser --version
kubewise --version
```

설치기는 사용자 로컬 폴더에 EXE 한 벌을 설치하고 하드링크로 두 이름을 등록한 뒤 사용자 PATH를 추가합니다. **두 파일명이 보이지만 같은 파일 데이터를 참조**합니다. PowerShell 별칭이나 프로필 수정 없이 PowerShell/CMD 모두 사용할 수 있습니다. 기존 터미널 앱은 저장된 PATH 반영을 위해 재시작이 필요할 수 있습니다.

관리자 권한·네트워크 연결은 필요 없습니다. 로컬 NTFS 등 하드링크 지원 파일시스템이 필요하며 미지원 시 복제하지 않고 실패합니다. 다운로드한 스크립트가 정책에 의해 차단되면 조직의 서명/차단 해제 절차를 따르세요. 설치기가 실행 정책을 낮추지는 않습니다.

같은 버전 재설치는 멱등이며, 다른 바이너리는 새 해시별 디렉터리에 설치됩니다. 이전 버전 디렉터리와 PATH 항목은 자동 삭제하지 않습니다. 설치 충돌은 기존 파일을 덮어쓰지 않고 거부합니다. 이전 PowerShell 별칭이나 시스템 PATH의 동명 명령이 있으면 해제/정리가 필요할 수 있습니다.

### 고도화 계획

[로드맵과 레퍼런스](https://github.com/uknowpro/kubewiser/blob/v0.1.0-alpha.5/docs/roadmap.md)를 추가했습니다. P0 입력/보고서 → P1 로컬 스키마/버전 규칙 → P2 읽기 전용 수집 → P3 Helm/drift → 업그레이드·관측·클라우드 이전 순서입니다. 이 단계들은 계획이며 이번 릴리스에 구현된 검사 기능이 아닙니다.

### 검증·제약

Windows PowerShell 5.1에서 설치·재실행·충돌 보호와 CMD/PowerShell 두 명령 실행을 검증합니다. Windows 32/64비트 모두 제공하며 CI는 Windows Server 2022/WOW64입니다. Windows 10 실기기 검증은 미완료입니다. Windows는 미서명, macOS는 Developer ID 서명·공증 미적용입니다. 기존 초기 알파 검사 범위(1.16~1.32 입력, YAML 및 일부 API 제거 규칙)와 미검사 항목은 유지됩니다. 외부 텔레메트리·자동 리포팅·스키마 다운로드는 추가하지 않았습니다. MCP 클라이언트의 외부 전달은 별도입니다.

## English

### Automatic registration of both Windows commands

Windows ZIPs include one `kubewiser.exe` plus `install.ps1`. Run once in PowerShell from the extracted directory:

```powershell
.\install.ps1
kubewiser --version
kubewise --version
```

The installer places one executable in user-local storage, creates two hardlink names, and updates user PATH. **Two names are visible, but they share the same file data.** PowerShell and CMD work without shell aliases or profile changes. Restart existing terminal applications if needed to refresh PATH.

No administrator privileges or network requests are required. A local hardlink-capable filesystem such as NTFS is required; unsupported filesystems fail instead of copying a second executable. Follow organizational signing/unblocking procedures if script execution policy prevents installation. The installer does not weaken execution policy.

Same-version installation is idempotent. Different binaries use separate content-hash directories; old version directories and PATH entries are retained for manual cleanup. Conflicting files are not overwritten. Existing aliases or same-name commands earlier in system PATH may require cleanup.

### Development plan

Added a [roadmap and primary references](https://github.com/uknowpro/kubewiser/blob/v0.1.0-alpha.5/docs/roadmap.md): input/report quality, local schemas/version rules, read-only snapshots, Helm/drift, then upgrade/observability/cloud migration. These are planned stages, not newly implemented inspection features.

### Validation and limits

Windows PowerShell 5.1 tests cover installation, repeat runs, conflict protection, and both commands in PowerShell/CMD. Windows x86/x64 are provided; CI uses Windows Server 2022/WOW64, not Windows 10 devices. Windows binaries remain unsigned; macOS binaries are not Developer ID signed or notarized. Existing alpha inspection scope (1.16–1.32 inputs, YAML and selected removed API rules) and unchecked areas are unchanged. No external telemetry, automatic reporting or schema downloads are added. MCP client forwarding is a separate concern.
